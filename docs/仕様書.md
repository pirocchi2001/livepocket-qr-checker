# LivePocket QR重複チェック WEBアプリ 仕様書

最終更新: 2026-09-10

## 1. 概要

LivePocketの電子チケットQRコードをカメラで読み取り、**同じQRコードの二重入場を防止する**ための受付支援Webアプリ。
GitHub Pages(静的ホスティング)+ Firebase(Firestore, Authentication)の無料枠のみで運用できる構成。

## 2. 技術スタック

| 項目 | 内容 |
|---|---|
| フロントエンド | Next.js 14 (App Router, TypeScript), Tailwind CSS |
| ビルド方式 | 静的エクスポート (`output: 'export'`)。サーバー機能は一切使用しない |
| ホスティング | GitHub Pages(GitHub Actionsで自動デプロイ) |
| データベース | Firebase Firestore (Sparkプラン/無料枠) |
| 認証 | Firebase Authentication(メール/パスワード。管理画面ログイン専用) |
| QRデコード | `html5-qrcode`(カメラ映像からのリアルタイムデコード) |
| ハッシュ化 | `crypto-js`(SHA-256) |
| Excel出力 | `xlsx`(SheetJS) |
| リポジトリ | `github.com/pirocchi2001/livepocket-qr-checker` |
| 公開URL | `https://pirocchi2001.github.io/livepocket-qr-checker/` |
| Firebaseプロジェクト | `livepocket-qr-checker`(ロケーション: asia-northeast1 東京) |

## 3. 判定ロジック(コア機能)

1. `html5-qrcode` がカメラ映像からQR文字列を検出
2. QRの内容を問わず(※後述の経緯により文字列チェックは廃止)、`crypto-js`のSHA-256でハッシュ化
3. そのハッシュ値をドキュメントIDとして、Firestore `scans` コレクションに対して `runTransaction` を実行
   - ドキュメントが存在しない → 新規作成(`{ scannedAt: serverTimestamp(), rawText }`)+ 通過人数カウンターを+1 → **OK(緑)** を約1.2秒表示し自動でスキャン再開
   - ドキュメントが存在する → **NG(赤)** + 初回読み取り日時を表示 → 「確認(次へ)」ボタンで手動再開
4. QRコードの中身(`rawText`)は、OK/NG画面どちらにも大きく表示される

トランザクションを用いるため、**複数端末が同時に同じQRを読んでも、必ずどちらか一方だけがOK、もう一方は必ずNGになる**(競合状態に強い設計)。

`invalid`(読み取りエラー)状態は、通信エラー等の処理失敗時のみのフォールバックであり、通常のフローでは発生しない。

### 経緯: 「livepocketという文字列を含むか」チェックの廃止

当初は「QR文字列に"livepocket"を含むか」で有効性を判定する仕様だったが、実際のLivePocketチケットを解析した結果、本物のQRコードには意味を持たない64文字程度のBase64ライクな不透明トークンが埋め込まれており、"livepocket"という文字列は含まれていないことが判明した(チケット画面上に別途テキスト表示されている「チケット番号」と、QRの中身は別物)。そのため、このチェックは完全に廃止し、QRコードの内容を問わず受け付ける仕様に変更した。

## 4. データモデル (Firestore)

### `scans/{hash}` (hash = QR文字列のSHA-256)

| フィールド | 型 | 説明 |
|---|---|---|
| `scannedAt` | Timestamp | サーバー生成の読み取り日時 |
| `rawText` | string | QRコードの中身そのもの(最大2000文字) |

過去にOCRで取得した `serialNumber` / `ticketNumber` / `surname` / `givenName` フィールドは、機能自体を撤回したため**現在は保存していない**。

### `meta/counter` (単一ドキュメント)

| フィールド | 型 | 説明 |
|---|---|---|
| `totalCount` | number | 通過人数(全端末合計)。スキャン成功のたびに`increment(1)`で更新 |

**運用上の注意**: このドキュメントはセキュリティルール上、公開create不可のため、**Firebase Console等で事前に手動作成しておく必要がある**(`{ totalCount: 0 }`)。作成し忘れると、カウンター更新の失敗によりスキャン処理全体が失敗するため注意。

## 5. Firestoreセキュリティルール(最終版)

```
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /scans/{hash} {
      allow get: if true;
      // 一覧取得(list): 管理画面(認証済み)は無制限。
      // 認証なしのアクセス(PC画面のスキャンログ表示用)は
      // 1回のクエリで最大300件までに制限。
      allow list: if request.auth != null
                  || (request.query.limit != null && request.query.limit <= 300);

      allow create: if request.resource.data.keys().hasOnly(['scannedAt', 'rawText'])
                    && request.resource.data.scannedAt == request.time
                    && request.resource.data.rawText is string
                    && request.resource.data.rawText.size() <= 2000;

      allow update: if false;
      allow delete: if false;
    }

    match /meta/counter {
      allow get: if true;
      allow list: if false;
      allow update: if request.resource.data.keys().hasOnly(['totalCount'])
                    && request.resource.data.totalCount == resource.data.totalCount + 1;
      allow create, delete: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

設計方針: 受付端末に認証を持たせない(誰でもスキャン可能にする)代わりに、書き込める内容を「新規作成のみ・フィールド限定・サイズ上限」まで絞り込むことで安全性を担保している。

## 6. 画面構成

### 6.1 トップ画面(スキャン画面) `/`

PC/スマートフォンをUser-Agentで自動判定し、レイアウトを出し分ける(`ScanScreen.tsx`)。

**スマートフォン(1カラム)**
- タイトル
- 通過人数(`PassCounter`、全端末共有・リアルタイム表示)
- QRスキャナー(`QrScanner`)
- 管理画面へのリンク

**PC(2カラム、母艦として利用可能)**
- 左: QRスキャナー(固定幅420px)
- 右: スキャンログ(`ScanLogPanel`)
  - **OK(通過)分**: Firestoreの`scans`コレクションをリアルタイム購読(`onSnapshot`)し、全端末共有・保存され続ける(ページ再読み込みしても消えない)。直近300件まで表示
  - **NG(重複)・読み取りエラー**: Firestoreに保存しない設計のため、**発生したその端末だけの一時的な表示**(他端末やPCには共有されない)
  - 「表示をクリア」ボタン: 画面上の表示のみを空にする(Firestore上のデータ、重複チェックの記録は一切削除されない)

### 6.2 管理画面 `/admin`

Firebase Authentication(メール/パスワード)でログインした管理者のみアクセス可能。

- ログイン後、「最新の履歴を取得」ボタンで全履歴を取得(件数制限なし、`orderBy('scannedAt','asc')`)
- 一覧表示: No / 読み取り日時 / QRの内容 / 識別ID(ハッシュ)
  - スマートフォンで見た場合、表は横スクロールで閲覧する仕様(折り返しはしない)
- 「Excelでダウンロード」ボタン: `livepocket-scan-history_YYYYMMDD.xlsx` として出力
- 「表示をクリア」ボタン: 画面上の一覧を空にするのみ(Firestoreのデータは削除されない)
- 「← スキャン画面に戻る」リンクあり

## 7. デプロイ構成

- GitHubリポジトリへのpushをトリガーに、GitHub Actions (`.github/workflows/deploy.yml`) が `npm run build` → `./out` を GitHub Pages にデプロイ
- ビルド時、Firebase設定値(6項目)はGitHub Secretsから環境変数として注入され、静的ファイルに埋め込まれる(NEXT_PUBLIC_プレフィックス)
- `NEXT_PUBLIC_BASE_PATH` はワークフロー内でリポジトリ名から自動生成

## 8. 既知の制限事項・仕様上の判断

1. **QR内容の真正性チェックはしていない**: 「livepocketを含むか」のチェックを廃止したため、任意のQRコード(全く無関係なもの含む)を受け付けてしまう。真の意味での「偽造チェック」をするには、LivePocket側の公式検証APIとの連携、または事前に有効チケットリスト(CSV等)をアプリに読み込ませて完全一致照合する方式への変更が必要(未対応。要検討)。
2. **OCR機能は実装→撤回済み**: 一時期、カメラ映像から画面上の「氏名」「整理番号」「チケット番号」をTesseract.jsでOCR認識する機能を実装したが、複雑さに起因する不具合が頻発したため、ユーザーの要望により完全に削除し、コア機能(QR読み取り+重複防止)のみに戻した経緯がある。再度必要になった場合は本ドキュメントの「9. 今後の検討事項」を参照。
3. **NG(重複)・読み取りエラーは端末間で共有されない**: Firestoreに保存しないため、PC(母艦)側で他端末のNG発生を一括監視することはできない。必要であれば専用コレクションへの記録を追加する拡張が可能。
4. **一覧取得(list)を一部公開している**: PC画面のスキャンログ表示のため、認証なしでも直近300件まではFirestoreから読み取れる状態になっている。QRの中身(意味のない文字列)と読み取り時刻が誰でも閲覧できる点に留意。
5. **通信量**: 見積もりでは、来場者数千人規模のイベントを1日中稼働させても1台あたり数MB〜10MB程度と想定(Firestoreのリアルタイム購読は差分のみ送信されるため、ポーリング方式よりも軽量)。確実な数字が必要な場合は実機での実測を推奨。

## 9. 今後の検討事項(未対応・要相談)

- 有効チケットリスト(LivePocket管理画面からのエクスポートを想定)との完全一致照合による、真の意味での偽造検知
- NG/エラーもFirestoreに記録し、PC側で全端末の異常を一括監視できるようにする
- 通過人数のイベントごとのリセット機能(現状は手動でFirebase Consoleから`totalCount`を0に書き換える運用)
- 受付終了フラグ、時間帯別グラフなど、運営向け追加機能

## 10. 開発・運用上の注意点(申し送り)

- コードの変更は、開発環境からZIPファイルとして渡され、利用者がローカルで展開・上書き→`git add`/`commit`/`push`する運用フローで進めてきた
