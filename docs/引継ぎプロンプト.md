## プロジェクト概要

- 目的: LivePocketの電子チケットQRコードをスマホ/PCのカメラで読み取り、**同じQRコードの二重入場(二重登録)を防止する**受付支援Webアプリ
- 技術スタック: Next.js 14 (App Router, TypeScript) + Tailwind CSS、静的エクスポート(`output: 'export'`)、GitHub Pagesでホスティング、Firebase Firestore(Sparkプラン/無料枠)+ Firebase Authentication(管理画面ログイン用)
- リポジトリ: `github.com/pirocchi2001/livepocket-qr-checker`(GitHubアカウント名: pirocchi2001)
- Firebaseプロジェクト: `livepocket-qr-checker`(ロケーション: asia-northeast1)
- 公開URL: `https://pirocchi2001.github.io/livepocket-qr-checker/`

詳細な仕様は、リポジトリ内 `docs/仕様書.md` を必ず読み込んでから作業を開始してください。判定ロジック、データモデル、Firestoreルール、画面構成、既知の制限事項がすべて記載されています。

## 開発フロー上の重要な制約(必ず守ること)

1. **あなたはユーザーのPC上のファイルを直接編集できません。** コード変更は、あなたの作業環境でファイルを編集・ビルド検証した上で、変更後のプロジェクト一式をZIPにまとめてユーザーに渡し、ユーザー側で展開・上書き→`git add`/`commit`/`push`してもらう、という流れで進めてください。
2. **コードを渡す前に、必ずローカルで`npm install`→`next build`を実行し、ビルドが通ることを確認してください。** これを怠ると、ユーザー側でのみ発覚するビルドエラーが多発し、ユーザーに何度も同じ作業をやり直させることになります(過去に実際に発生し、ユーザーに大きな負担をかけました)。
3. **複数ファイルにまたがる変更をする場合は、変更したファイル全てを漏れなくZIPに含めてください。** 過去に、一部ファイルだけが反映されず、削除したはずのモジュールへの参照が別ファイルに残ってビルドが失敗する事故が発生しています。ユーザーには`git status`で全ての変更が反映されているか確認するよう伝えてください。
4. **Firestoreのセキュリティルールの変更は、コードのpushとは別に、Firebase Console上で手動で「公開」してもらう必要があります。** ルールを変更した場合は、その旨と具体的な手順(コンソールのどこを開くか)を明示してください。
5. **`.github/workflows/deploy.yml`(GitHub Actionsのワークフローファイル)への変更は、通常のgit push(OAuthアプリ経由)では`workflow`スコープ不足により拒否されます。** このファイルを変更する必要がある場合は、GitHubのWeb UI(ブラウザ)から直接編集してもらうよう案内してください。
6. **もしブラウザ操作ツール(Chrome連携など)が利用できる場合は、Firebase ConsoleやGitHubの画面操作を代行できますが、以下は絶対に代行しないでください**: パスワード・APIキー・トークンなどの認証情報の入力、アカウントの新規作成、金銭が発生する操作の実行。これらはユーザー自身に行ってもらい、あなたは画面遷移やクリックなど非機密操作のみサポートしてください。

## これまでの経緯で特に重要なもの

- 当初「QR文字列に"livepocket"を含むか」で真正性を判定する仕様だったが、実際のチケットQRを解析した結果、本物のQRにもこの文字列が含まれていないことが判明し、このチェックは完全に廃止した(詳細は仕様書参照)。
- 画面上のテキスト(氏名・整理番号・チケット番号)をOCR認識する機能を実装したが、不具合が多発したため、ユーザーの要望で完全に撤回し、コア機能のみに戻した。OCRを再度検討する場合は、この失敗の経緯を踏まえて慎重に設計すること。
- `meta/counter`ドキュメント(通過人数カウンター)は、Firestoreルール上、公開create不可のため、機能追加時にFirebase Console上で手動作成が必要。作成し忘れるとスキャン処理全体が失敗する。
